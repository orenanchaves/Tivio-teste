API TLDR

Cálculo financeiro e Análise de Carteira, por HTTP

A API TLDR concentra a matemática de retorno e risco da Tivio e serve as tabelas prontas da Análise de Carteira. Ela é chamada do servidor, nunca do navegador, com um token do Entra ID.

Primeira chamada

  1. Entre no tenant da Tivio pelo Azure CLI 
    az login --tenant 28bfc1cb-5aa5-436f-9b59-4bbea6096aee \
  --scope api://ae37bc8e-f16d-47fb-99ab-9d3dd0cc2201/.default
  2. Pegue um token da API 
    TOKEN=$(az account get-access-token \
  --scope api://ae37bc8e-f16d-47fb-99ab-9d3dd0cc2201/.default \
  --query accessToken -o tsv)

    O token vale cerca de 1 hora. Sem ele, a plataforma responde 401 antes de a requisição chegar à API.

  3. Confira se a API está de pé 
    curl -H "Authorization: Bearer $TOKEN" \
  https://wa-tivio-tldr-brsouth.azurewebsites.net/v1/carteira/status

    Mostra o motor de leitura, a versão de cada tabela e o que ainda falta carregar. Não consulta o banco.

Passo a passo

Receitas completas, do token ao número. Escolha a que parece com o seu caso; cada passo depende do anterior.

Você já tem as cotas (ou um número-índice) e quer retorno por janela, volatilidade e drawdown. Nada é lido do banco: a API calcula sobre o que você envia.

  1. Monte o corpo com duas listas do mesmo tamanho

    dates em AAAA-MM-DD e values com o nível da cota naquele dia, não o retorno. A ordem não importa: a API ordena.

    # serie.json (dados de exemplo; a série completa tem 15 dias)
{
  "dates":  ["2026-09-30", "2026-10-01", "2026-10-02", …],
  "values": [1.5273481, 1.52827978, 1.52907449, …]
}
  2. Peça o retorno por janela 
    curl -sS -X POST "https://wa-tivio-tldr-brsouth.azurewebsites.net/v1/finance/period-returns" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d @serie.json
    Resposta gerada pela API com dados de exemplo
    {
  "WTD": 0.0017109691515113656,
  "MTD": 0.006569373412649071,
  "YTD": null,
  "6M": 0.006569373412649071,
  "12M": 0.006569373412649071,
  "24M": 0.006569373412649071,
  "36M": 0.006569373412649071,
  "60M": 0.006569373412649071,
  "since_inception": 0.006569373412649071
}

    Tudo em decimal: 0,00657 é 0,66%. Janelas maiores que a série repetem o retorno desde o início, e o YTD vem null quando a série não cruza a virada do ano: confira a primeira data antes de mostrar 12M ou 60M.

  3. Peça a volatilidade anualizada 
    curl -sS -X POST "https://wa-tivio-tldr-brsouth.azurewebsites.net/v1/finance/volatility?period=252" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d @serie.json
    Resposta gerada pela API com dados de exemplo
    {
  "volatility": 0.004711266766147014
}

    Desvio padrão amostral dos retornos diários × √252. period é quantas observações há num ano: 252 para série diária, 12 para mensal.

  4. Mesma série, outras métricas

    /max-drawdown, /drawdown-series e /var-historic (pede ao menos 10 retornos) usam o mesmo corpo. Sharpe, Sortino, tracking error, alfa/beta e correlação pedem duas séries: fund_dates/fund_values e a do benchmark ou da taxa livre de risco.

Você sabe qual é o fundo, mas não tem as cotas. A API busca a cota no Databricks e calcula as mesmas métricas da receita anterior.

  1. Identifique o fundo

    CNPJ só com dígitos é o caminho direto. cod_fundo e isin também são aceitos e são traduzidos para CNPJ numa tabela de cadastro; se vier CNPJ, ele vence. Para limpar um CNPJ digitado com pontuação, use GET /v1/utils/normalize-cnpj.

  2. Escolha o intervalo

    start e end entram inteiros (inclusive). O retorno é medido a partir da primeira cota que existir no intervalo: para YTD, comece no último dia útil do ano anterior.

  3. Chame a rota by-fund 
    curl -sS -X POST "https://wa-tivio-tldr-brsouth.azurewebsites.net/v1/fundcalc/by-fund/period-returns" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"cnpj": "<CNPJ do fundo>", "start": "2025-12-31", "end": "2026-10-21"}'

    A resposta tem o mesmo formato de /v1/finance/period-returns. Sharpe e Sortino por fundo usam sempre o CDI como taxa livre de risco.

  4. Vários fundos de uma vez

    POST /v1/fundcalc/by-funds/cotas devolve as cotas de até 100 CNPJs num intervalo. Um CNPJ sem cota não aparece em results: compare a lista que voltou com a que você pediu.

Você quer o que a aba Alocação da Análise de Carteira mostra: exposição por setor, classe, rating, book, gestor e estratégia de um fundo numa data.

  1. Descubra a última data disponível 
    curl -sS -H "Authorization: Bearer $TOKEN" \
  "https://wa-tivio-tldr-brsouth.azurewebsites.net/v1/carteira/referencia"
  2. Peça a alocação

    codigo é o código Maravi da carteira. visao=expandida abre os fundos investidos; base mostra a carteira como está.

    curl -sS -D - -H "Authorization: Bearer $TOKEN" \
  "https://wa-tivio-tldr-brsouth.azurewebsites.net/v1/carteira/fundos/940/alocacao?data=2026-10-20&visao=expandida"
  3. Leia o cabeçalho de sign-off

    Por padrão a resposta é do último dia com sign-off até a data pedida. X-Signoff-Date diz qual dia veio; vazio quer dizer que o fundo ainda não tem dia aprovado e a resposta veio vazia. Para ver a data pedida mesmo sem aprovação, acrescente &signoff=false.

  4. Mostre os números

    exposure está em reais e pct é fração do PL. A soma dos baldes pode passar de 100% do PL, porque a exposição considera derivativos e alavancagem.

Dentro do Informativo não há token na mão: o cliente src/lib/tldr/client.ts pega o token da identidade do App Service.

  1. Configure o ambiente
    VariávelValor
    TLDR_REST_BASE_URLhttps://wa-tivio-tldr-brsouth.azurewebsites.net
    TLDR_REST_RESOURCEae37bc8e-f16d-47fb-99ab-9d3dd0cc2201 (o appId da API)
    ENV_MODEprod no App Service (identidade gerenciada); local usa o seu az login
    CARTEIRA_API1 para as telas lerem a carteira pela API
  2. Chame com o helper 
    import { tldrGet } from "@/lib/tldr/client";

// Lança TldrHttpError (com .status) em erro HTTP
const ref = await tldrGet<{ data: string }>("/v1/carteira/referencia");
  3. Na Análise de Carteira, use a reserva

    As telas não chamam a API direto: passam por viaApiOuReserva, que cai no SQL antigo se a API falhar e pausa só aquele endpoint por 30 s. Ela já acrescenta signoff=false, porque a tela interna mostra também o que não foi aprovado.

    const linhas = await viaApiOuReserva(
  `/v1/carteira/fundos/${id}/var?${qs({ data })}`,
  () => varDatabricks(id, data),   // caminho antigo, se a API não responder
  { fatia: "var" },
);
  4. Teste local sem token

    Com a API rodando no seu computador (uvicorn, sem Easy Auth), defina TLDR_REST_SEM_TOKEN=1 e aponte TLDR_REST_BASE_URL para http://localhost:8000. Em produção essa variável é ignorada.

Para notebook, relatório ou job: a mesma identidade do az login, pelo SDK do Azure.

  1. Instale as dependências 
    uv add azure-identity requests
  2. Pegue o token e chame 
    import requests
from azure.identity import DefaultAzureCredential

BASE = "https://wa-tivio-tldr-brsouth.azurewebsites.net"
ESCOPO = "api://ae37bc8e-f16d-47fb-99ab-9d3dd0cc2201/.default"

token = DefaultAzureCredential().get_token(ESCOPO).token
s = requests.Session()
s.headers["Authorization"] = f"Bearer {token}"

r = s.post(f"{BASE}/v1/finance/volatility", json={
    "dates": ["2026-10-19", "2026-10-20", "2026-10-21"],
    "values": [1.53561536, 1.53656744, 1.53738182],
}, timeout=30)
r.raise_for_status()
print(r.json()["volatility"])
  3. Trate os erros pelo status

    422 traz em detail o campo ou o valor errado; 503 é para tentar de novo em alguns segundos. O token dura cerca de 1 hora: em job longo, peça outro antes de vencer.

Sign-off: o que sai por padrão

As rotas da Análise de Carteira devolvem, por padrão, só dado de fundo com sign-off do Risco. Pediu 20/10 e o último dia aprovado é 17/10: a resposta é de 17/10 e vem com o cabeçalho X-Signoff-Date: 2026-10-17. Fundo sem nenhum sign-off volta vazio. Para a data pedida, sem esse filtro, envie signoff=false — é o que a tela interna do Informativo faz.

Nenhuma rota com esse termo. Tente o nome da tabela (fund_allocation), da métrica (sharpe) ou do campo.
